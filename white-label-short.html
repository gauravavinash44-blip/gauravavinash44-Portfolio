Overview

Guests see the firm. The hub has to be true.

Systematic is a US fintech. An investor invites a company in. That guest lands on the investor’s URL, sees the firm logo, and gets mail from the firm. White Label Setup is the Settings page that makes those three things real.

The job

Product Designer II. One month. I owned the Settings hub: subdomain, logo, and sender. Login, signup, and email templates were already there.

The problem

v1 had shipped as a packed form. Domain radios. Upload Logo with no URL. A sender row that said Verified on first visit.

What shipped

Empty start. Then a live URL, a logo, and a verified sender. No completion number yet. I’d track drop-off next.

The problem

The page looked live before anything was set.

On first open, White Label Setup already had domain radios, an Upload Logo slot, and a sender marked Verified. An admin with nothing configured still looked like a firm that was done. Guests would have seen that as the firm.

Who this is for

One person sets it. Everyone else just sees it.

Primary Investor / firm admin

Opens Settings. Sets a prefix, a logo, and a sender. If they change the prefix, old invite links stop working. They need to see that before they save.

Affected Invited company / co-investor

Never opens this page. They get an invite, land on the firm URL, and read mail from the firm. If the hub is fake, they see the fake.

Internal Product / engineering

DNS for the subdomain, file storage for the logo, and a verification wait for the sender. The UI has to hold empty, pending, and verified. Not one pretty row.

Constraints

One month. Settings hub only.

v1 was already in the product. I wasn’t rebuilding identity. I was making this page tell the truth, with the same components Settings already uses.

Time

Four weeks. Hub only. Login, signup, and email templates stay as they are.

Logo

No URL, no Upload Logo. SVG, PNG, JPEG, or HEIC. Up to 5MB.

URL and mail

Change the prefix and old invite links die. New sender email has to verify again. Delete lives in the edit dialog, not on the page.

Decisions

Three calls. The rest of the page follows them.

I didn’t reopen login or mail templates. I picked three fights on this page.

Empty first, not a filled form

The packed form was faster to leave alone. It also told a lie on day one. I needed a first visit that looks like work still to do.

Keep v1

Radios, logo slot, Verified row. Admins still have no create path. Guests still see a finished firm.

Two create buttons

Create Subdomain. Create Sender. Nothing on the page looks live until they finish those jobs.

Went with the empty hub. Live is a result, not a skin.

Logo only after a URL

A logo with no domain is a sticker. Guests see the mark on the firm URL. If that URL doesn’t exist yet, the upload has nowhere to go.

Upload on the empty page

Looks complete. Then you save a logo that no invite can point at.

Unlock after save

Prefix in. Locked suffix .systematicventures.com. Then Upload Logo sits under that live URL.

Hide Upload Logo until the subdomain exists.

Sender has its own states

Mail from the firm is the third piece guests see. A Verified badge on an empty row skips the wait that engineering actually has.

Keep “Verified” as default

Pretty. False. No resend. No reason to Edit.

Empty, pending, resend, verified

Create Sender first. Then Pending Verification with Resend (60s). Edit stays on every state. New email means verify again.

The row is honest about where the address is.

The flow

Investor sets it. Company sees it.

The admin path is a line. The company path is what that line produces.

Empty start. Live end.

Step 01 · Empty hub

Subdomain

Create. Then edit.

The prefix is theirs. The suffix is ours: .systematicventures.com. Changing the prefix kills old invite links, so the edit dialog says that, and it adds Delete. Create does not.

Sender

Empty, pending, resent, verified

The row has to wait on a real inbox. Edit stays on every state so they can fix a typo without losing the object.

Sender form

Create. Then edit.

Email, name, street, country, state, city, zip. A bad email blocks Submit. Change the email later and verification starts over. Delete is in this dialog, not on the hub.
