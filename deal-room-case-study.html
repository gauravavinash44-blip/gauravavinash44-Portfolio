What is a Deal Room?

Explain the product before the solution.

Investors evaluating startups receive information from multiple disconnected places—before any single decision is made.

  • Company profiles, emails, financial documents, NDAs, calls, WhatsApp, Google Drive

Because everything happens across different tools:

  • Information gets lost
  • Trust decreases
  • Decisions become slower
  • Founders repeatedly answer the same questions

Primary Problems

Three blockers that shaped every design decision.

Each problem maps to a solution pillar—not a screen inventory.

Problem 1

No structured deal journey

Founders uploaded information randomly. There was no guidance. Investors received inconsistent information.

  • No shared structure for participants
  • Deal work split across disconnected surfaces
  • No bridge from discovery intent to commitment

Before: messy workflow → After: guided workflow

Problem 2

Trust happened outside the platform

NDA, document sharing, and permissions lived in email and drive—investors continuously switched platforms.

Problem 3

No visibility into deal progress

Founders couldn't answer: Who viewed? Who signed the NDA? Who downloaded files? Who showed investment interest?

  • Engagement was guesswork
  • No readiness signals for next actions
  • Teams misaligned on deal maturity

Design Principles

How we aligned on trade-offs before pixels.

Reduce Cognitive Load

One decision at a time—complexity only when context requires it.

Guide Step-by-Step

Linear setup with clear next actions—not blank-slate anxiety.

Build Trust Progressively

NDA and permissions surfaced before sensitive access.

Keep Investors Focused

Deal context stays intact—no tab-hopping to evaluate.

Surface Actions at the Right Time

CTAs appear where intent already exists.

Solution

Three problems, three design responses.

For every screen: why it exists, what user problem it solves, and how it supports the business.

Response to Problem 1 · Structured journey

Deal Room creation lives where intent already exists.

Why: Users don't start with deals—they start with companies.

User problem: No natural trigger to begin a structured deal.

Business: Increase deal creation from profiles.

  • Create Deal Room on company profile when no room exists.
  • Switch to Deal Room when a room is already active.
  • Auto-selected company context at creation—less setup friction.

First-run modal set expectations before setup began

Deal builder · Final design

We simplified deal setup into a clear, linear flow with minimal backtracking.

Guided setup from company context to live deal room

Improved clarity during deal creation

Iterations

Design thinking—not just polished screens.

Each major feature moved through hypothesis, exploration, feedback, and refinement.

Entry point on company profile

Problem→ Hypothesis→ Sketches→ Wireframes→ User feedback→ Changes→ Final UI

Problem: Deal creation was buried—users never reached structured flow.

Hypothesis: Placing CTA on the company profile would lift adoption without adding steps.

Change: Discarded isolated nav entry; anchored creation to profile intent.

+32% deal creation from company profiles

NDA gating

Problem→ Hypothesis→ Wireframes→ User feedback→ Final UI

Problem: Legal steps happened off-platform—trust eroded at the gate.

Change: Collapsed multi-step legal maze into four in-context screens with preview before sign.

Higher NDA completion; fewer support escalations

Progress dashboard

Problem→ Hypothesis→ Wireframes→ Final UI

Problem: Founders couldn't see engagement—everything was guesswork.

Change: Readiness signals and role-based views replaced static status lists.

Founders prioritized follow-ups with evidence, not intuition

Key Learnings

  • Designing for trust means showing obligations before access—not after.
  • Business goals (NDA completion, deal creation) must map to user moments.
  • Enterprise workflows need progressive disclosure, not feature dumps.

What I'd apply next time

  • Entry points define adoption more than downstream polish.
  • Structure without access is useless—trust and visibility ship together.
  • Products that scale need shared mental models across founder and investor roles.
